# Design — Tournament Console

<!-- impeccable:design-doc -->

Scope: `src/tournament/webapp/static/` (the live dashboard). Written at finish, from the built result — not a spec drafted ahead of the build.

## Mode

Operate. A single-user research console — the visitor is completing a task (read standings, compare models, watch a live run), not being persuaded or shown a portfolio piece. Familiarity and density outrank expression; the interface should disappear into the task.

## World

The dashboard's visual language is derived directly from the project's own vocabulary rather than an invented brand: strategy names are literally `snake_case` Python identifiers, moves are literally the characters `C`/`D`, and the payoff matrix has one structurally "best" cell (`T=5`, mutual defection's temptation payoff / exploitation) and one cooperative-equilibrium cell (`R=3`). The design borrows those facts directly:

- **Wordmark/nav** set in mono, lowercase, `pd://tournament` — reads like a URL scheme / module path, not a logotype.
- **Accent = "payoff gold"** (`#d99a3f`) — not a picked brand color; it's a nod to the payoff matrix's highest-value cell, used sparingly (primary action, active nav, chart accents) per the Restrained color strategy.
- **Cooperate/defect get their own semantic pair** (teal `#4fd1ae` / coral `#e2685a`) used *only* for C/D move chips, log lines, and the two research-question line charts — never as decoration elsewhere.
- **Provider colors** are a second, distinct qualitative palette (classic=gray, groq=gold, ollama cloud=blue, ollama local=muted blue, anthropic=plum) used for standings bars and badges — kept visually separate from the cooperate/defect pair so the two color systems never collide in the same chart.

## Color strategy

Restrained: near-black graphite ground (`--bg: #0f1115`), a raised neutral layer for the sidebar/panels (`--bg-raised: #15181e`), one accent. Dark-first — a late-night, data-dense research tool reads better on dark than on a bright ground, and it makes the chart series pop.

Full token list lives in `style.css`'s `:root` block — treat that as the source of truth, not this file.

## Typography

One family for UI (IBM Plex Sans), one for everything numeric/technical (IBM Plex Mono — strategy names, model tags, scores, log lines, C/D chips). Monospace is earned here, not a "technical" costume: the content it's applied to (identifiers, tabular numbers, move sequences) genuinely is code/data/measurement. Fixed rem scale, tight ratio (~1.15), no fluid/clamp sizing — per Operate-mode convention, not brand-surface convention.

## Layout

Fixed 248px left sidebar (wordmark + six-item nav + status indicator), single scrolling main column, one `<section class="view">` per nav item toggled by a plain hash router — no framework, no build step. Panels (`.panel`) are the only repeating container; deliberately not icon+heading+text cards, which the craft floor flags as the lazy default.

## Components

- **Data table**: `.data-table`, mono uppercase column headers, tabular-nums, hover row highlight.
- **Badge**: pill with a colored dot, used for provider/model tags.
- **Move chip**: 1.6em square, mono, colored by cooperate/defect semantics.
- **Heatmap**: hand-rolled CSS grid (no charting library needed for a matrix), labels truncate with ellipsis + `title` tooltip on overflow — long strategy names (`llm_ollama_cloud_gemma4_31b_cloud`) are the normal case, not an edge case.
- **Log line**: one line per SSE event, color-keyed by event type (`match_end` = cooperate teal, `match_error`/`run_error` = defect coral).
- **Progress bar**: `transform: scaleX()`, not `width`, to avoid layout-property animation.

## Charts

Chart.js via CDN, no bundler. `Chart.defaults` set once (mono font, palette colors) so every chart inherits the system instead of Chart.js's own defaults. Qualitative series colors come from `qualitativeColor(i)` (a fixed hue rotation), independent of the provider palette, since chart series and provider badges answer different questions and were confusable when sharing one palette during build.

## Known gaps / next time

- No responsive collapse below ~1000px sidebar+content threshold beyond the two-column-panel breakpoints already in `style.css` — this is a desktop tool by brief, mobile was not a target.
- The embedded spatial-grid GIF (`spatial_evolution.gif`) carries its own white matplotlib background, which visibly clashes with the dark shell. Out of scope for this build (the GIF is generated by `visualization.py`, not the webapp) — worth revisiting if that generator ever gets a dark-mode-aware background.
